# Releasing RadarVector

Releases are built by `.github/workflows/release.yml` when a `v*` tag is
pushed. The workflow produces a **draft** GitHub release; publish it by hand
after checking the assets.

## Artefacts

| Platform | Files |
| --- | --- |
| macOS (Apple Silicon + Intel) | `RadarVector_<v>_universal.dmg` (signed + notarised when the Apple secrets exist) |
| Windows x64 / ARM64 | `RadarVector_<v>_<arch>-setup.exe` (NSIS), `RadarVector_<v>_<arch>.msi` (WiX), `…_portable.zip` |
| Linux x64 | `.deb`, `RadarVector_<v>_x86_64.AppImage`; Flatpak manifest in `packaging/flatpak/` |
| All | `latest.json` + `*.sig` (minisign signatures for in-app updates) |

Each package ships `LICENSE-MIT`, `LICENSE-APACHE`, `THIRD_PARTY_LICENSES.html`
(generated by `cargo about`) and the CC-BY-SA attribution of the bundled data.

## One-time setup

1. **Update signing key** (mandatory for in-app updates):
   ```bash
   cargo install --locked cargo-packager
   cargo packager signer generate --path radarvector-update.key
   ```
   - Secret `UPDATE_PRIVATE_KEY` = content of `radarvector-update.key`
   - Secret `UPDATE_PRIVATE_KEY_PASSWORD` = its password
   - Repository variable `UPDATE_PUBLIC_KEY` = content of `radarvector-update.key.pub`
   Keep the private key offline as well: losing it means users cannot verify future updates.
2. **macOS**: Apple Developer ID Application certificate exported as .p12, base64 →
   `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`; `APPLE_SIGNING_IDENTITY`
   (e.g. `Developer ID Application: Name (TEAMID)`); notarisation with
   `APPLE_ID`, `APPLE_PASSWORD` (app-specific password), `APPLE_TEAM_ID`.
3. **Windows**: code-signing certificate .pfx, base64 → `WINDOWS_CERTIFICATE`,
   `WINDOWS_CERTIFICATE_PASSWORD` (or replace the import step by Azure Trusted Signing).

Without the Apple/Windows secrets the workflow still builds, but packages are unsigned.

## Steps

1. Bump `version` in the root `Cargo.toml` (`[workspace.package]`) and the
   release entry in `packaging/linux/net.radarvector.RadarVector.metainfo.xml`.
2. `cargo test --workspace` and, on a machine with a GPU,
   `cargo test -p radarvector-app --release -- --ignored` (visual + UI tests).
3. Tag and push: `git tag v0.2.0 && git push origin v0.2.0`.
4. Check the draft release, then publish it. `latest.json` becomes visible to
   installed apps through `releases/latest/download/latest.json`.

## Verifying an update locally

```bash
F=RadarVector_0.2.0_universal.dmg
RV_SIGNED_FILE=$F RV_SIGNATURE_FILE=$F.sig RV_PUBLIC_KEY_FILE=radarvector-update.key.pub \
  cargo test -p radarvector-feed --test packager_signature -- --ignored
```
